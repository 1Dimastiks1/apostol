# Автоматичне оновлення Facebook

Сайт має серверний модуль, який щохвилини перевіряє Graph API, оновлює стрічку подій, останнє відео та найновіше оголошення про богослужіння. Дописи й відео старші за 14 днів не повертаються у сайт. Оголошення розкладу на сторінці показує дату публікації Facebook і її повний текст — дата та зміст замінюються разом із новим дописом.

## Підключення

1. Створи застосунок у Meta for Developers та отримай Page Access Token для сторінки парафії `100059029128700`. Для читання контенту керованої сторінки Meta вказує `pages_read_engagement`, `pages_read_user_content` і `pages_show_list`; потрібні доступи та App Review залежать від ролі й режиму застосунку.
2. Скопіюй `.env.example` у `.env` і додай токен у `FACEBOOK_PAGE_ACCESS_TOKEN`. Не додавай `.env` до Git і не вставляй токен у HTML або браузерний JavaScript.
3. Якщо Meta окремо дозволить читання дописів профілю настоятеля, задай його numeric ID та User Access Token у `FACEBOOK_RECTOR_PROFILE_ID` і `FACEBOOK_RECTOR_USER_ACCESS_TOKEN`. Для дописів користувача Graph API вимагає дозвіл `user_posts`, наданий власником профілю; доступ до особистого профілю може бути недоступним для цього застосунку.
4. Запусти `npm run dev` для розробки. Для локального запуску зібраного сайту виконай `npm run build`, потім `npm run serve`; API та сайт мають працювати на одному сервері.

Синхронізація опитує Facebook раз на 60 секунд, тому новий допис з’явиться на сайті за хвилину. Це не вебхук реального часу: миттєві сповіщення потребують окремого Meta App, верифікованого webhook URL і підписки сторінки. Якщо токен не налаштований або Meta відмовила в доступі, сайт показує резервні записи не старші за 14 днів і повідомляє про стан підключення.

Довідка Meta: [Page API](https://developers.facebook.com/docs/graph-api/reference/page/) · [Post API та читання дописів профілю](https://developers.facebook.com/docs/graph-api/reference/post/).
